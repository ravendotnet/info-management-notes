# O1 LO3 - HISTORY OF DATABASE
## HISTORY OF DATABASE
<ul>
<li><b></b></li>
<li><b>1960s</b>: Computers become cost effective for private companies, and storage capacity increases.</li>
<li><b>1970-72</b>: E. F. Codd proposes the relational model for databases, disconnecting the logical organization from the physical storage.</li>
<li><b>1976</b>: P. Chen proposes the entity relationship model (ERM) for database design.</li>
<li><b>Mid-1980s</b>: SQL (Structured Query Language) becomes "intergalactic standard.</li>
<li><b>Early 1990s</b>: An industry shakeout begins with fewer surviving companies. Oracle survives.</li>
<li><b>Mid-1990s</b>: Kaboom! The usable Internet/World Wide Web (WWW) appears. A mad scramble ensues to allow remote access to computer systems with legacy data.</li>
<li><b>Late 1990s</b> : The large investment in Internet companies helps create a tools-market boom for Web/Internet/Database connectors.</li>
<li><b>Early 21st century</b>: Solid growth of DB applications continues. Examples: commercial websites (yahoo.com, amazon.com, google.com), government systems (Bureau of Citizenship and Immigration Services, Bureau of the Census), art museums, hospitals, schools, etc.</li>
</ul>


## DATA DEVELOPMENT PROCESS
<ol>
    <li><b>Step 1</b>: Data modeling begins by researching the information requirements of a business.
        <ul>
            <li><b>Entity Relationship Diagram (ERD)</b> should completely capture and accurately model the organization’s information needs and support the functions of the business.</li>
        </ul>
    </li>
    <li><b>Step two</b>: the database design phase of the development process, translates the information modeled on the entity relationship diagram to a table instance chart.
    The table instance chart lists the design specifications of the information and has the following components:
        <ul>
            <li><b>Table name</b></li>
            <li><b>Column names</b></li>
            <li><b>Keys</b>: a <b>Primary Key (PK)</b> is the unique identifier for each row of data; a <b>Foreign Key (FK)</b> links data in one table to the data in a second table by referring to the PK column in the second table.</li>
            <li><b>Nulls</b>: indicates if a column must contain a value (mandatory).</li>
            <li><b>Unique</b>: indicates if the value contained in a column is unique within the table.</li>
            <li><b>Datatype</b>: identifies the definition and format of the data stored in each column</li>
        </ul>
    </li>
</ol>
<ul>
        <li><b>Structured Query Language (SQL)</b> commands are used to build the physical structure of the database.SQL is also used to populate, access, and manipulate the data within the relational database.</li>
    </ul>
