# SO2 L03 - ENTITY RELATIONSHIP DIAGRAM 
<ul>
    <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
        <p role="presentation"><strong><span style="font-size:11pt;font-family:Arial,sans-serif;">Entity Relationship Diagram (ERD)&nbsp;</span></strong><span style="font-size:11pt;font-family:Arial,sans-serif;">- is a consistent tool that can be used to represent the data requirements of a business regardless of the type of database that is used, and even in the absence of one!</span></p>
    </li>
</ul>

<img src="./assets/S02-L03/{A27B52EC-B842-4FE6-836B-A66D1BF5B799}.png">

<ul>
    <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
        <p role="presentation"><strong><span style="font-size:11pt;font-family:Arial,sans-serif;">Implementation-Free Models</span></strong><span style="font-size:11pt;font-family:Arial,sans-serif;">&nbsp;- A good conceptual data model stays the same regardless of the type of database the system is eventually built&mdash;or implemented&mdash;on. This is what we mean when we say that the model is &ldquo;implementation-free.&rdquo;</span></p>
        <ul>
            <li>The data model should stay the same even if a database is not used at all. For example: when the data is eventually stored on pieces of paper in a filing cabinet.</li>
        </ul>
    </li>
</ul>


<ul>
    <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
        <p role="presentation"><strong><span style="font-size:11pt;font-family:Arial,sans-serif;">What is an Entity Relationship Model</span></strong></p>
        <ul>
            <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;"> Is a list of all entities and attributes as well as all relationships between the entities that are of importance.
            </li>
            <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
                <p role="presentation">Provides background information such as entity descriptions, data types, and constraints.</p>
            </li>
            <li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
                <p role="presentation">Note: The model does not require a diagram, but the diagram is typically a very useful tool.</p>
            </li>     
        </ul>
    </li>
</ul>

<li style="list-style-type:disc;font-size:11pt;font-family:Arial,sans-serif;">
    <p role="presentation"><strong><span style="font-size:11pt;font-family:Arial,sans-serif;">Goals of ER Modelling</span></strong></p>
    <ol>
        <li style="list-style-type:decimal;font-size:11pt;font-family:Arial,sans-serif;">
            <p role="presentation"><span style="font-size:11pt;font-family:Arial,sans-serif;">Capture all required information</span></p>
        </li>
        <li style="list-style-type:decimal;font-size:11pt;font-family:Arial,sans-serif;">
            <p role="presentation"><span style="font-size:11pt;font-family:Arial,sans-serif;">Ensure that information appears only once</span></p>
        </li>
        <li style="list-style-type:decimal;font-size:11pt;font-family:Arial,sans-serif;">
            <p role="presentation"><span style="font-size:11pt;font-family:Arial,sans-serif;">Model no information that is derivable from other information already modeled</span></p>
        </li>
        <li style="list-style-type:decimal;font-size:11pt;font-family:Arial,sans-serif;">
            <p role="presentation"><span style="font-size:11pt;font-family:Arial,sans-serif;">Locate information in a predictable, logical place</span></p>
        </li>
    </ol>
</li>
